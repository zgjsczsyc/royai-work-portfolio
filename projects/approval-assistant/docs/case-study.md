# 案例：把分散的审批材料整理成可核对的信息

## 问题

审批人需要在不同系统读取表单和附件。字段名称、结构与日期格式可能不一致，采购明细也需要核对。若模型直接接收缺失或错误的数据，语言流畅的总结可能掩盖材料问题。

## 目标用户与目标

面向需要复核流程材料的审批人。先保证模型输入有明确来源、数据类型和完整性状态，再生成辅助总结；最后由人查阅原始材料并作出审批决定。

## 方案

以 Dify 组织请假与采购两条路径，统一字段、规则与附件信息，形成一致的模型输入。关键字段或必需附件缺失时直接停止；采购金额由确定性代码校验。模型负责提炼已有信息、解释核对结果和列出待确认事项。

主要展示入口为 Dify Cloud 的[【正式demo】企业审批辅助助手](https://udify.app/chat/oQZ7k3O8Q6O0aGPU)，云端演示可运行。云端版内置虚构数据，真实调用所配置的模型；采购回调只展示说明，不保存或写回。仓库另保留本地接口版，通过 Mock 演示 API 取数、JWT 和内存模拟写回。已发布的 Web 应用当前无需工作区权限；工作流编辑仍需要授权。

## 本演示包含的工作

- 将业务核对要求表达为流程规则、必需字段与附件清单。
- 对接两种模拟数据结构，统一嵌套字段、日期和金额的处理。
- 设计失败分支及人工处理提示，避免缺规则时继续给出建议。
- 使用本地 Mock 和回归测试验证已知错误场景。
- 提供无需本地接口的云端演示版，便于在 Dify Cloud 展示工作流与模型总结。

本案例说明公开展示版的设计与验证范围。原业务系统部署、历史团队分工和未披露的生产成效不在本仓库的证据范围内，详见[展示范围与资料说明](../../../DISCLOSURE.md)。

## 三分钟演示顺序

1. 从 README 的工作流图说明输入、规则获取、系统适配和人工审批边界。
2. 打开已发布的 Web 应用，选择 `10086 / OA / LEAVE`，展示输入材料与模型生成的辅助总结。
3. 切换 `20099 / BPM / PURCHASE`，展示确定性金额核对及模拟回调说明，解释内置演示数据与实际业务集成的边界。
4. 展示回归测试中的缺规则、缺附件和错误金额场景；需要说明接口集成时，可补充运行 `python demo.py`，这一本地脚本不调用模型。

## 结果与限制

当前证据包括 36 项本地自动化测试，以及用户于 2026-11-02 确认 Dify Cloud 演示可运行。尚无真实上线覆盖人数、审批耗时变化或模型准确率数据，也未补齐逐场景云端运行记录。后续可用固定合成样本衡量关键字段遗漏、无依据结论、异常分支覆盖与运行耗时，再记录模型和版本以便复现。
