# 案例：把分散的审批材料整理成可核对的信息

## 问题

审批人需要在不同系统读取表单和附件。字段名称、结构与日期格式可能不一致，采购明细也需要核对。若模型直接接收缺失或错误的数据，语言流畅的总结可能掩盖材料问题。

## 目标用户与目标

面向需要复核流程材料的审批人。先保证模型输入有明确来源、数据类型和完整性状态，再生成辅助总结；最后由人查阅原始材料并作出审批决定。

## 方案

以 Dify 组织两条系统适配路径，通过接口获取字段配置和规则，形成一致的模型输入。关键字段或必需附件缺失时直接停止；采购金额由确定性代码校验。模型仅负责提炼已有信息、解释核对结果和列出待确认事项。BPM 场景将总结写回模拟服务，并向用户显示写回状态。

## 本演示包含的工作

- 将业务核对要求表达为流程规则、必需字段与附件清单。
- 对接两种模拟数据结构，统一嵌套字段、日期和金额的处理。
- 设计失败分支及人工处理提示，避免缺规则时继续给出建议。
- 使用本地 Mock 和回归测试验证已知错误场景。

这些内容说明仓库当前展示的实现范围，不代表对历史团队分工、个人独立完成范围或实际生产效果的声明。面试介绍时应结合本人实际经历说明承担的工作。

## 三分钟演示顺序

1. 从 README 的工作流图说明输入、规则获取、系统适配和人工审批边界。
2. 运行 `python demo.py`，展示 OA 日期与姓名整理、BPM 金额校验及模拟写回核验；说明这一步没有调用模型。
3. 展示 `python -m unittest discover -s tests -v` 的异常测试，包括缺规则、缺附件和错误金额。
4. 完成 Dify 实机验收后，再展示真实模型生成的总结及故障分支。未完成前不使用预写文本冒充模型结果。

## 结果与限制

当前证据是本地测试和演示链路，尚无真实上线覆盖人数、审批耗时变化或模型准确率数据。后续可用固定合成样本衡量关键字段遗漏、无依据结论、异常分支覆盖与运行耗时，再记录模型和版本以便复现。
